直近の技術 Q&A を学習ノート vault に保存します。同じトピックの既存ノートがあれば追記、なければ新規作成。

## いつ使うか

- 技術的な質問に答えた直後にユーザーが「学習ノートに追記」「保存」「メモして」等と返した時
- ユーザーが任意のタイミングで `/save-learning-note` を直打ちした時(直近の技術 Q&A を拾う)
- **使わない**:
  - プロジェクト固有の作業手順(別 docs に書く)
  - バージョン依存ですぐ陳腐化する一時的な調査
  - 雑談・確認応答

## vault の前提

- パス: `C:\Users\shint\Documents\学習ノート\`
- Obsidian 管理。一部フォルダ(`aws/`, `ITパスポート/`)は独立 git リポなので**コミットには関与しない**(書き込みのみ)
- 大カテゴリフォルダ + トピック単位 `.md` 1 ファイル構成
- フォーマット: `# <トピック> メモ` → 1 行導入 → `---` → `## 1. xxx` ナンバリング章立て、表/箇条書き多用

カテゴリは Glob で都度確認(増減する可能性あり)。

## 進め方

1. **直近会話から技術知識を抽出**:
   - 直前のユーザー質問とアシスタント回答を起点に、**再利用価値のある部分**(概念定義・トレードオフ・ハマりどころ・選定理由・ベストプラクティス)を抽出
   - プロジェクト固有のコード/作業手順は除外
   - トピック名の候補を 1-3 個挙げる(例: 「pgvector」「HNSW インデックス」「ベクトル検索」)

2. **vault 構造を確認**:
   - `Glob` で `C:\Users\shint\Documents\学習ノート\*` のフォルダ一覧と `**/*.md` を取得
   - 推定カテゴリと該当しそうな既存ファイル候補を挙げる(例: `データベース/PostgreSQL.md` に追記候補)
   - トピックがどのカテゴリに属するか自信が無いときは候補を複数提示

3. **保存先をユーザーに確認** (`AskUserQuestion`):
   - **保存先**: 既存ファイルに追記 / 新規ファイル作成 / カテゴリ変更
   - 新規時は **カテゴリフォルダ** と **トピック名** を続けて確認(2 ラウンド目)
   - 候補が外れていたらユーザーに正解カテゴリを聞く

4. **追記の場合**:
   - 既存ファイルの末尾を `Read` し、最終ナンバー(`## N. ...`)を確認
   - 新セクションは `## N+1. <セクション名>` で構成
   - 直前に `---` セパレータを置く
   - 既存スタイル(表 / 箇条書き / 太字 `**...**` 強調)を踏襲。長文散文は避ける
   - サブセクションは `### xxx` を使う

5. **新規作成の場合**:
   - パス: `C:\Users\shint\Documents\学習ノート\<カテゴリ>\<トピック>.md`
   - 既存ファイル名と被らないか `Glob` で確認
   - 雛形:
     ```markdown
     # <トピック> メモ

     <1 行で「これは何か」要約>

     ---

     ## 1. <最初のセクション>

     ...
     ```

6. **書き込み前にプレビュー**:
   - どのファイルにどのセクションを足す(または新規作成する)かを差分形式で表示
   - `AskUserQuestion` で **書き込む / 修正する / キャンセル** を取る
   - 「修正する」なら指摘を反映して再提示
   - 「書き込む」で `Edit`(追記)または `Write`(新規)を実行

7. **完了報告**:
   - 書き込んだファイルの絶対パスを表示
   - Obsidian で開けることを示唆(必要ならリンク化: `obsidian://open?vault=学習ノート&file=...`)

## ルール

- **ファイル冒頭の H1 は `# <トピック> メモ`** 形式に統一(既存全ファイル準拠)
- **ナンバリング `## N. xxx`** を維持(追記時は最終番号 +1)
- **`---` セパレータ** をトップレベルセクション間に置く(既存スタイル準拠)
- **表 / 箇条書きを多用**。長文散文は避ける
- **シークレット情報を書かない**(API キー・パスワード・社内 URL の認証情報など)
- **プロジェクト固有の情報を入れない**(shipyard 専用の話なら学習ノート対象外。普遍的に再利用できる知識のみ)
- **既存ファイルを上書きしない**(必ず `Edit` による追記、または新しいファイル名で `Write`)
- **`.git` を持つフォルダ内でも `git` コマンドは打たない**(書き込みのみで完了)
- **書き込み前に必ずユーザー確認**(プレビュー → yes/no/修正)
- ユーザーが「保存して」と即決した場合でも保存先(追記 or 新規)は必ず確認する
